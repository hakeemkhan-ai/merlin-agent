# Security, quality, and bug review — 2026-11-06

Reviewed the current source snapshot and implemented the confirmed findings below.
The scope includes API admission/authentication, durable tool recovery, GitHub
publishing and OAuth, workspace/checkpoint paths, browser/LSP isolation, context,
terminal presentation, verification tooling, and deployment configuration.
Repository execution and automated checks ran in a disposable E2B workspace.

## Confirmed findings and fixes

Severity reflects the deployed single-owner service and its isolated workspaces.
Every application/tooling finding was reproduced by a failing regression before
the fix. Deployment findings were checked against vendor advisories.

| ID | Severity | Finding | Implemented fix |
| --- | --- | --- | --- |
| S01 | High, conditional on local files | The verification source uploader included `.ssh`, `.kube`, `.netrc`, `.git-credentials`, nested credential directories, and some private-key containers. Those files could be transferred to E2B unintentionally. | Check all path components case-insensitively against credential names and suffixes; reject links and special files. Keep source and `.env.example` usable. |
| S02 | Medium | API request bodies were buffered before bearer authentication, and FastAPI parsed malformed JSON before its authentication dependencies. Unauthorized clients could consume the upload allowance/deadline and receive validation details. This was an availability gap, not a successful authentication bypass. | Perform a constant-time owner-header check before buffering protected requests. Reject duplicate authorization headers. Retain route-level authentication and the signed-state GET OAuth callback. |
| B01 | Medium | Resolving one uncertain tool always requeued the task, even when other results or mutation intents remained unresolved. The worker would pause it again, and a second immediate operator resolution would fail until then. | Keep the task paused until all unresolved outcomes are acknowledged, using the same predicate as explicit resume. Queue only after the final resolution. |
| B02 | Low | The terminal ignored `tool.operator_resolved`, leaving acknowledged tools in its uncertain-operation picker and making subsequent resolution attempts conflict. | Mark the entry `resolved`, show the operator note, and preserve the distinction from a successful tool execution. |
| D01 | High, exposure-dependent | Compose pinned Grafana 11.6.0 and Prometheus 3.2.0 within published vulnerability ranges. | Pin Grafana 12.4.14 and Prometheus 3.13.5, and document upgrade/backup checks. No deployed services or volumes were changed. |

S01 is a demonstrated unsafe inclusion policy, not evidence that real credentials
were disclosed during this review. Reproductions used synthetic fixture values.

The dependency findings include Grafana's
[CVE-2025-4123 frontend plugin XSS](https://grafana.com/security/security-advisories/cve-2025-4123/)
and Prometheus's
[CVE-2026-42154 unauthenticated remote-read memory exhaustion](https://github.com/prometheus/prometheus/security/advisories/GHSA-8rm2-7qqf-34qm).
Grafana is bound to host loopback and Prometheus has no host port in this Compose
configuration, which limits exposure without fixing vulnerable software.
The chosen versions are published vendor releases:
[Grafana 12.4.14](https://github.com/grafana/grafana/releases/tag/v12.4.14) and
[Prometheus 3.13.5](https://github.com/prometheus/prometheus/releases/tag/v3.13.5).
Prometheus 3.13 is the currently supported
[LTS line](https://prometheus.io/docs/introduction/release-cycle/).

## Operating changes and limits

Restart the API and workers to load the application changes. No application
schema migration or new environment variable is required. Multiple uncertain
outcomes now remain paused until each is acknowledged. An acknowledgement still
does not undo effects, mark success, or replay an operation.

Grafana changes major version. Follow the backup and provisioning checks in
[operations](operations.md) before rolling out the Compose update. Image changes
have not been deployed, and existing Grafana database migrations, dashboards,
and live scraping still require an operational smoke check.

The Python dependency scan does not scan container operating-system packages or
the separately installed Node/Playwright/LSP toolchain. The monitoring advisory
review is targeted, not a full image vulnerability scan; other pinned images
still need that scan and a supported-version review. Live Gemini/GitHub App
calls, publishing/revocation, and container startup were not run in E2B as part
of this review. Mocked versions are exercised by the deterministic suite.
The root `.git` directory is empty; the pre-push recheck recovered the existing
publish history and scanned all available commits. Repository credential
filenames are filtered, but neither filtering nor scanning establishes that
arbitrary source text or every historical secret is safe to disclose.

The example database password/URL now use an explicit random-password placeholder.
Set a unique generated password in the real configuration; never deploy a literal
example value. The push does not rotate credentials on running services.

The local filesystem filled during the first edit. The affected test file was
restored from the clean E2B snapshot before applying changes. Two ignored,
rebuildable caches (`.merlin/uv-cache` and `.merlin/verification-venv`) were moved
to `/tmp/merlin-security-2026-11-06-*`, with symlinks retaining their original
paths. The final source was compared against the pre-edit copy.
