# Security, correctness, and terminal audit — 2026-10-29

Requested workflow: inspect the whole repository, list findings, plan fixes, then
implement and verify. This document records the list and plan before application
code changes. It will be updated with reproduction and verification evidence.

The review uses ECC Security Review, Production Audit, and Verification Loop.
It covers application modules, migrations, deployment, scripts, evaluations,
tests, and the terminal interface. No Git history is available in this workspace.
Source snapshots and test commands run in a disposable E2B environment; local
credentials, `.env`, Git metadata, and generated state are excluded from uploads.

## Prioritized findings

These are code-review findings; regression tests will establish the failing
behavior before each fix. Severity describes the consequence within Merlin's
single-owner service and isolated-workspace model.

| ID | Priority | Finding and consequence | Location |
| --- | --- | --- | --- |
| A01 | High | A paused task with a persisted uncertain tool result can be resumed without resolving it. Recovery checks only unfinished intents, allowing the model to continue after an unacknowledged side effect. | `persistence/store.py`, `worker/__init__.py` |
| A02 | High | LSP source paths do not apply the secret-path restrictions used by file tools. A Python/TypeScript file under `credentials/` or an environment directory can be submitted to a language server. | `lsp/_remote.py`, `sandbox/__init__.py` |
| A03 | High | The GitHub broker rejects traversal and workflows but accepts secret paths such as `.env` and `.aws/credentials`. Task-level publishing permissions can publish files the source reviewer refuses to show. | `integrations/github.py` |
| A04 | High | HTTP request interception does not establish a WebSocket policy. Untrusted pages can bypass the browser's read-only external interaction rule using WebSockets. | `browser/_remote.py` |
| A05 | High | Session/repository consistency is checked outside the store transaction. Concurrent API submissions or direct store calls can mix repositories within a session. | `api/__init__.py`, `persistence/store.py` |
| A06 | Medium | A newly created workspace is registered for cleanup only after checkpoint restoration. Restore failure or cancellation can leave a paid sandbox running. | `worker/__init__.py` |
| A07 | Medium | Tool output is clipped in the top-level result but retained in full in `data`, sometimes alongside stdout/stderr. Large LSP results and shell output can exceed context bounds and defeat exact-output deduplication. | `sandbox/__init__.py`, `lsp/_remote.py` |
| A08 | Medium | A successful slow submission clears the composer even when the user has typed a new draft while waiting. | `tui/app.py` |
| A09 | Medium | A submission returning HTTP 5xx discards its idempotency key. An upstream/proxy failure after commit can cause duplicate tasks on retry. | `tui/app.py` |
| A10 | Medium | Changing server connections does not invalidate the view generation or cancel other outstanding UI workers. An old refresh/submission may update the new connection's view. | `tui/app.py` |
| A11 | Low | The E2B domain validator accepts private suffixes and malformed labels rejected by the API validator, creating inconsistent enforcement across entrypoints. | `api/__init__.py`, `sandbox/__init__.py` |
| A12 | Low | The verification driver runs `uv lock`, which can rewrite dependency resolution instead of checking the committed lock as its documentation promises. | `scripts/verify.py` |
| A13 | Medium | A queued composer-change event can access widgets after unmount and crash the terminal during shutdown. Reproduced by the existing baseline lost-response test. | `tui/app.py` |
| A14 | High | `allowed_url` recognizes a trailing-dot localhost name as local, but `local_url` does not. An external page can request `http://localhost.:PORT` and skip the local-origin checks. | `browser/_remote.py` |
| A15 | High | E2B's command/login-shell environment drops the Docker template's tool PATH and browser-cache setting. Browser startup fails and Python LSP reports unavailable even though those tools are installed. | `sandbox/__init__.py`, `sandbox/_remote.py`, `browser/_remote.py` |
| A16 | Medium | The agent executor forwards undeclared internal sandbox operations such as `apply_delta`. Such a model call bypasses the worker's mutation classification and can lose a completed delta after interruption. | `agent/__init__.py` |
| A17 | Medium | Stream prioritization starts newly running tasks without cancelling followers that left the three-task selection. Repeated changes can exceed the intended stream bound and increase API polling/connection load. | `tui/app.py` |
| A18 | Medium | The browser daemon has only a five-second readiness window. A real cold E2B launch exceeded it and reported failure, then became healthy; leaving that process alive also makes immediate retries unsafe. | `browser/_remote.py` |

## Fix plan

1. Add regression reproductions for the security and lifecycle findings (A01–A06),
   then fix store/worker fencing, path policy, browser WebSockets, and cleanup.
2. Bound result payloads without silently claiming complete output (A07), retaining
   artifacts when output needs truncation.
3. Fix submission and connection races and add headless terminal regressions
   (A08–A10). Use OpenCode as a reference for discoverable commands, file
   references, explicit review, and a portable Ctrl+J newline shortcut.
4. Unify network authorization and make verification read-only with respect to
   dependency resolution (A11–A12).
5. Run the full deterministic suite, Ruff lint/format, mypy, locked build, offline
   evaluations, and targeted real browser/LSP checks inside E2B. Inspect modified
   files against the pre-change snapshot. Record remaining deployment/live gates.

Follow-up found during execution: reproduce A14 and normalize local hostnames
consistently before re-running the browser-origin checks.
The actual adapter smoke also reproduced A15. Add explicit template tool-path
setup after the SDK/login-shell boundary, test interpreter/command selection with
real shell processes, and re-run the actual E2B browser/LSP/checkpoint smoke.
Also close the agent dispatcher over its declared tool names (A16); internal
delta application remains available through checkpointed child integration.
Enforce the existing three-follower limit when priorities change (A17), with a
regression that promotes a queued task while three other streams are active.
Give cold browser startup a bounded twenty-second window and clean up a daemon
that misses it (A18), then verify the actual adapter without diagnostic retries.

## Review coverage and operating implications

Reviewed the API/authentication and read projections, task contracts and settings,
worker recovery/cancellation, store transactions and migrations, sandbox file and
process helpers, browser and LSP adapters, GitHub/OAuth publishing broker, context
assembly, child integration, CLI/client/SSE handling, terminal state/screens,
telemetry, artifact retention, evaluation graders, verification/runtime scripts,
backup/restore logic, Docker/Compose/edge configuration, CI and dependency lock.
All application modules passed type checks and the deterministic test suite.

OpenCode's official TUI/keybinding documentation informed the interface review:
command palette, session selection, expandable tool output, `@` references, explicit
proposal review and a Ctrl+J newline fallback. Existing styling and 80×24 layouts
were preserved and exercised by real Textual widgets; this was not a UI rewrite.

No schema migration is needed. Restart idle API/worker processes to load the fixes.
Uncertain tasks require `/resolve` before `/resume`. Credential/key paths are now
blocked consistently; older checkpoints containing newly excluded paths require a
clean replacement. Browser WebSockets stay local to Playwright's interception and
never connect to a server; applications relying on sockets need a separate safe
origin policy. Large tool payloads use bounded previews and artifact references.

The locked Starlette 1.10.0 is above the 1.0.1 fix for the selected
[Host-header advisory](https://github.com/Kludex/starlette/security/advisories/GHSA-86qp-5c8j-p5mr).
This targeted primary-source advisory check is not a complete dependency CVE scan.
Secret-pattern checks were limited to source/configuration/fixtures; Git history
is unavailable here and is not certified free of secrets.

Remaining release gates are Docker image/Compose startup, a full deployed backup
restoration, physical-terminal input, live Gemini performance, and live GitHub
OAuth revocation/publishing workflows. The native PostgreSQL/HTTP/E2B checks above
do not replace those deployment- and provider-specific gates. No production
services, task records, or GitHub repositories were changed by this audit.
